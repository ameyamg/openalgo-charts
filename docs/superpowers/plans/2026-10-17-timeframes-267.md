# 2.6.7 Timeframes and Indicator History Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Native execution is recommended for this plan because the feed, indicator and host tasks share interfaces and require a strict validation order.

**Goal:** Support compatible custom timeframes, show a daily EMA 200 on a five-minute chart using independent history, and persist timeframe favorites, proving the SDK in the local yfinance example before integrating OpenAlgo `/trading`.

**Architecture:** Add opt-in provider-neutral resolution and resampling around existing feeds. Reuse the interval registry, session calendars, bounded cache, request pool and requested-indicator lifecycle. Keep broker capabilities in the host and share preference logic across the widget, reference host and consumer toolbar.

**Tech Stack:** TypeScript, existing dependency-free SDK tiers, JavaScript reference host, Python reference data server, React consumer, Vitest and Playwright.

**Spec:** [Approved design](../specs/2026-10-17-timeframes-267-design.md).

```ts
// Base-tier types and functions, exported through src/index.ts.
interface TimeframeBucket { time: number; from: number; to: number } // [from,to)
interface TimeframeSource {
  interval: string; // actual provider token
  bounds(time: number): TimeframeBucket | null; // provider timestamp convention
  earliest?: number;
  maxBars?: number;
  maxSpanSeconds?: number;
}
interface TimeframeMarket {
  key: string; // includes provider, calendar revision, session and adjustment policy
  calendar: SessionCalendar;
  sources: readonly TimeframeSource[];
}
interface TimeframePlan {
  interval: string;
  source: TimeframeSource;
  native: boolean;
  market: TimeframeMarket;
}
function planTimeframe(request: BarsRequest, market: TimeframeMarket): TimeframePlan;
function timeframeBucketAt(plan: TimeframePlan, time: number): TimeframeBucket | null;
function aggregateTimeframeBars(bars: readonly Bar[], plan: TimeframePlan): Bar[];
interface TimeframeFeedOptions {
  market(request: BarsRequest): TimeframeMarket;
  now?: () => number; // UTC seconds
}
interface TimeframeFeed extends DataFeed {
  resolve(request: BarsRequest): TimeframePlan;
  destroy(): void; // cancel only work/subscriptions owned by this wrapper
}
function withTimeframes(feed: DataFeed, options: TimeframeFeedOptions): TimeframeFeed;

// Indicator-tier API, exported through src/indicators/index.ts.
interface TimeframeProviderOptions {
  availability(bar: Readonly<Bar>, request: IndicatorSnapshotRequest): {
    at: number | null; confirmed: boolean;
  };
  historicalSnapshot?: (request: IndicatorSnapshotRequest) => Promise<RequestedBarsSnapshot>;
}
function createTimeframeProvider(feed: TimeframeFeed, options: TimeframeProviderOptions): IndicatorBarsProviderAccess;
interface TimeframeOptions {
  historyBars?: (settings: Readonly<IndicatorSettings>) => number;
}
function withTimeframe(descriptor: IndicatorDescriptor, options?: TimeframeOptions): IndicatorDescriptor;
```

Add optional `warmupBars?: number` to `IndicatorSnapshotRequest`: the number of confirmed requested observations required before `from`, in addition to the requested window. It does not change legacy `requestBars`. Add optional `supportsWarmup?: boolean` to `IndicatorBarsProviderAccess` and `IndicatorRequestState`; old providers default to false. Independent built-ins use only providers explicitly supporting this contract. Existing snapshot consumers retain their behavior.

The wrapper's `market` callback is synchronous after the host has loaded its metadata. Do not invent synchronous capabilities for an unresolved broker. `bounds` normalizes the provider's bar timestamp convention; it must not split an OHLC bar. Unknown source alignment permits native requests but refuses derived requests. All newly public types are exported and documented with their implementation task.
